# v0.2 validation

## Automated verification

- Production build passes (npm run build).
- All 32 tests pass (npm test).
- Coverage includes seeded movement consistency at 60/144/240 Hz, analytic sphere/capsule hits, cover occlusion and parallel AABB rays, tiny-target edge contact, instant colors and colorblind materials, head/body separation, lead/lag direction, reacquisition without firing, reveal placement, 150 ms head flashes, time-weighted timelines, target mesh reuse, and the 350 ms Jiggle Track respawn pulse.
- Damage still requires held input. On-target percentage measures aim contact independently of firing.
- Practice mode is captured at session start. Ghost markers only draw in practice, and practice results are excluded from scored history.
- The respawn pulse is canvas-only and begins after clearing a Jiggle Track target. It never changes target size, hitboxes, materials, or damage timing.

## Browser rendering check — 2026-10-09

Open /tests/performance.html on the Vite development server. The harness runs deterministic camera/movement input through the real runner and renderer. It is not a mouse-control or GPU execution-time benchmark.

Observed in the desktop app's Chromium browser, 960 × 540 CSS pixels at approximately 60 Hz:

| Scenario | Run | Mean frame | p99 frame | Worst frame | Mean simulation | Shader programs | Mid-run program changes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Jiggle Track | 30 s | 16.67 ms | 17.7 ms | 17.7 ms | 0.054 ms | 6 | 0 |
| Jiggle Info | 30 s | 16.66 ms | 17.7 ms | 17.8 ms | 0.039 ms | 7 | 0 |
| Slice the Pie | 30 s | 16.67 ms | 17.7 ms | 17.8 ms | 0.036 ms | 7 | 0 |

The first Jiggle Info measurement incorrectly included synchronous scenario loading in its first frame (65.8 ms). The harness timer was moved after configure/shader warm-up and the full 30-second Jiggle Info test was repeated; the table uses that repeat. Actual game session timing also starts after warm-up.

No console errors or shader-change warnings appeared during those runs. These measurements preceded the cosmetic respawn pulse; its behavior is covered by a regression test and a visual preview in the harness.

A CPU-only 60-second simulated run at 240 updates/s was also compared with the original Git HEAD in temporary directories:

| Scenario | Original mean update | Updated mean update |
| --- | --- | --- |
| Jiggle Track | 0.01593 ms | 0.00107 ms |
| Jiggle Info | 0.00811 ms | 0.00090 ms |
| Slice the Pie | 0.00840 ms | 0.00068 ms |

This single-process microbenchmark includes JIT effects and is evidence about CPU update cost only, not a GPU/FPS claim.
